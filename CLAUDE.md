# labs (labs.chuckwired.com)

Chuck's monorepo of small interactive experiments. Owner: Chuck (product designer, portfolio on Ghost at chuckwired.com).

## Shape
- `index.html`: landing page and nav. Labs are listed in the `LABS` array in its script; add an entry per lab. The index shows them newest first by `date` (the hidden lab always last), so array order doesn't matter; `tools/sync-seo.mjs` sorts the same way.
- `<lab-name>/index.html`: one folder per lab, each a self-contained static page. Link back to the index with `<a href="../">`.
- No build step, no dependencies. Vanilla HTML/CSS/JS. Use relative paths only (labs are served from subpaths).
- Visual system (colour, type scale, links, motion, voice) lives in `DESIGN.md`: read it before adding or restyling anything on the index or a text page, and update it when a token changes.
- Style: dark void `#07070a`, ink `#e8e6df`, dim `#8b8a93`; Instrument Serif (italic for titles), JetBrains Mono for UI. Sparse background dots. Fonts are self-hosted: link `shared/base.css` (fonts, tokens, global rules) and, on "Behind the design" pages, `shared/notes.css`; never add a Google Fonts link (`tools/check.mjs` fails it). Preload the two font files with the pattern in any existing page.
- `404.html` is generated: edit `tools/404-dots/template.html` (markup/CSS/script) or re-trace with `gen.mjs`, then `node tools/404-dots/build.mjs` (see its README); the still is not in the repo. The figure is a canvas with `role="img"` and a description; the headline has a visually hidden "404" and the burger is `aria-hidden`; reduced motion shows the finished figure and disables the hover scatter. Its "Behind the design" page is `behind-the-404/` (linked from the 404 itself, not registered in `LABS`). `404.html` at the root is served by DO for unknown paths from any URL depth, so it is the one file that must use absolute paths (`/`) and inline styles.
- Primary card button: each `LABS` entry can set `cta` (the filled button's label, default "Dive in"; an arrow is added). Set so far: capes "Suit up", pipes "Screen save", birthday "Let's pet", HKG Crossing "Walk the walk" (Chuck's wording); hidden lab "Capture the flag"; ocean is still "Dive in".
- Cover art: each `LABS` entry can set `cover: '<lab>/cover.svg'` (400x190 viewBox, flat art) or a PNG of the same ratio (`windows-pipes/cover.png` was rendered from the lab itself). Covers are PNG originals in `originals/<lab>/cover.png`; pages load the `.webp` made by `tools/optimise-images.mjs` (see `IMAGES.md`). `shatter: true` on an entry makes the card break into squares on click. The capes cover is generated from the lab's own cape code: run `node tools/make-cover.mjs` after changing cape art.
- Page transitions: cross-document View Transitions (`@view-transition { navigation: auto }`, off under reduced motion) on the index and every lab. The card's `.art` and the lab's main surface share the name `lab-art` (card named by script during the transition; lab names its stage in CSS). Browsers without support just navigate normally. Speculation rules prefetch (never prerender: the labs run render loops) the next page.
- Method: `.claude/skills/new-idea-routine/SKILL.md` is Chuck's routine for new labs (ideate, build three directions in parallel, test honestly, write the "Behind the design" page, publish-safety check). When asked to "use the new idea routine", follow it. It is public on purpose; keep it free of paths, emails, tokens and anything about the machine.
- Shared code is deliberately tiny: `shared/base.css`, `shared/notes.css`, `shared/fonts/`. Labs keep their own look inline. Change a token in `shared/base.css` first.
- Search: `tools/sync-seo.mjs` generates `sitemap.xml`, `llms.txt` and the `<noscript>` lab list in `index.html` from `LABS` (pre-commit does it). Every public page needs a unique title, description, canonical, `og:*` tags and JSON-LD (copy a neighbour); `noindex` pages and the secret lab are left out. `robots.txt` is hand-written. Add a new page to `tools/sync-seo.mjs` `extra` if it isn't a lab.
- Checks: `node tools/check.mjs` (links, alt text, head tags, no Google Fonts, image copies current, sitemap valid, and `tools/lint-pages.mjs`: every `LABS` entry and every `*/direction/` page is held to a standard. Pages that predate a rule are listed in its `LEGACY` map as warnings; new pages get the full rules. Start a write-up from `tools/templates/direction.html`) and `node tools/weigh.mjs` (per-page weight). The "Performance" page (`performance/`) quotes both plus Lighthouse; update it when they change.
- Archives: a lab's earlier builds live in `<lab>/archive/` (noindex). The notes page is `<lab>/direction/`.
- Images: full-quality originals go in `originals/<same path>/`, never linked; run `node tools/optimise-images.mjs` to make the `.webp` that pages use; `--check` before merging. Details and the deploy exclusion in `IMAGES.md`.
- Adding a lab: create folder + `index.html`, include the doctype/viewport/theme-color head and a "← Labs" back link, then add it to `LABS`.

## rs2-capes lab
Interactive RuneScape skill capes (herblore, mining, cooking, magic) drawn as layered SVG, no image assets. Click a cape to bring it forward, mouse-driven 3D tilt (max ±25° Y, ±15° X, no back view), others blur and dim, Esc or click away returns. Picker top right chooses which show; choice stored in localStorage (`cape-void:shown:v2`). Occasional shooting stars.
- Everything tunable is in `CONFIG` at the top of the script. `CONFIG.capeStyle = { herblore: 'rs3' }` (`osrs` variant is kept, do not delete). `defaultShown = 'all'` (every cape on a first visit; a list of ids also works).
- Model: back plate in trim colour (hangs slightly below hem), extrusion slices, body panel with six curved sections, emblem, shoulder pads, V collar. Light comes from screen centre via `--lx`.
- Perf architecture (keep): idle capes are one flat SVG; the 3D stack is `display:none` until focused; style writes cached; loop stops when page hidden; frame governor `goLite()` drops blur/stars/glow pulse if frames average >26ms; `LOWPOWER` builds fewer layers on weak devices.
- Perf update (v1 tag `v1-20261020` is the checkpoint before this): artwork is built on demand (flat SVG only while a cape is shown, the 16-layer stack only while focused, dropped after); colour-independent geometry, clip paths and the six-section shading live once in `sharedDefs()` and are `<use>`d per cape (pixel-identical to before). Above `CONFIG.crowdAt` (10) shown capes: no per-cape blur, no glow pulse, no idle tilt, light taken from resting position. At 29 capes: 4,682 -> 1,346 DOM nodes, 898KB -> 144KB markup, load 4.6s -> 2.3s (headless Chrome, 60fps held at 1x). On a throttled CPU (2x/4x, software raster) 29 capes is still not smooth; the first focus click shows a ~1s long frame in headless. Needs a real-phone check.
- Capes (12): herblore, mining, cooking, magic (original four, approved, never touch) plus agility, thieving, fletching, smithing, fishing, firemaking, woodcutting, farming (branch `rs2-all-capes`, the 99+ skills from Chuck's RS3 skills-tab screenshot). The new eight were traced from the OSRS Wiki's 3D cape renders (reference only, not shipped): emblems are the render's flat colours outlined and simplified to low-poly paths (`emAgility()` etc., 0.5-2.2KB each), palettes sampled from the render and tuned by eye against it. Method: pick the emblem's exact flat colours, label pixels, trace loops, Douglas-Peucker simplify, centre on (60,135). `tools/make-cover.mjs` was updated for the shared `<defs>` (it bakes a per-cape copy) and still reproduces the cover.
- Trim toggle: a "Trim On/Off" pill next to "Capes" (stored in localStorage `cape-void:trim`, default on). Trim on = the coloured edges (back plate `trim` + inner band `trim2`); off = body-hued edges from each cape's `plain` colours (original four derive `plain` from the body: outer lighter, middle darker). Rule for trim on, from the OSRS trimmed-cape renders and Chuck's own convention: `trim2` = the shoulder-pad colour, `trim` = a darker shade of it (the new eight follow this; the original four already did). Toggling rebuilds the built artwork in place (`look(c)`). With trim on the original four are pixel-identical to before.
- Stress testing: `?stress=N` (N up to 60) pads the list with recoloured copies of the real capes and shows them all (never saved). The temporary in-picker Max button has been removed.
- Decisions Chuck made: shoulder pads and the large focused view are approved, do not change. Shading approved. Disappear transition mirrors the intro but shorter. Title bottom-left uses Jersey 10 (closest free match to the in-game font), orange `#ff981f`, 2px hard black shadow.
- Open: mobile used to force-restart (suspected memory pressure); perf work done and Chuck has since tested all labs on an iPhone 17 Pro Max (Oct 2026): smooth, no restarts, 120 fps wherever an FPS readout exists. Older/cheaper phones still untried.

Same dot-field background as capes, no shooting stars. ## birthday-dog lab
Birthday card for Mama Candy with Otto the shih tzu (three.js 0.160.0 from jsDelivr via import map: the one lab with a CDN dependency; vendor it if that matters). Not a void lab: its own look, Pop direction (white + pale grey checker floor, near-black ink, one red accent `#e8321e`, headline in Anton sentence case, Archivo for UI). Dog is procedural (instanced fur tufts, toon shader, ink outlines), no model files. Tunables in `CONFIG` at the top of the script (`sitLift` 0.35 / `standLift` 0.3 were set by hand, `awkwardLeg` = front left, `sitTurn`, `dashEvery`, `floorDark`, `tile`, `cakePeekAt`, `cakeLitAt`, mic `blowLevel`/`blowTime`).
- Flow: loads with the candle lit and Otto sitting side-on to the cake. Blow it out by tapping the cake/bottom of the screen or the "Blow into your mic" button (mic permission only on that button). Cake then peeks from the bottom-left; tapping the bottom brings it back diagonally and lights it. Idle: Otto sometimes sprints off left and back in from the right. Toy is draggable (screen-space grab radius ~60-70px). C key = cake.
- "Behind the design" link slides in diagonally from the bottom-right corner when a mouse is near it (not shown on touch); page at `birthday-dog/direction/`, screenshots in `direction/shots/`. The three original directions (pop, golden, void) are archived under `birthday-dog/directions/` and tag `birthday-dog-three-directions`; all `noindex`.
- Decisions Chuck made: Pop over Golden Hour/Void Party; milder, larger checker; no dialog (cake is the control); underbite slightly softer; Otto's front-left leg sticks out sideways; Anton sentence case; hint is "Make a wish. Blow into your mic".
- Mic: asks for permission on load (and silently again each time the candle is relit); if refused the hint becomes "Make a wish. Tap the candle." plus a "Try the mic" button. The audio context is woken on the first touch/key. Asks for raw audio (echo cancellation, noise suppression and auto gain off, because they flatten a blow), judges a blow against the room's own loudness (`blowMin`, `blowRatio`, `blowTime`), does not await `AudioContext.resume()` (it can stay pending), and the flame leans as you blow. Verified against Chrome's fake mic only; Chuck reported the first version did nothing on real mics.
- Index card uses `fit: 'cover'` (`.plate.fill`), cover is a 1.5:1 screenshot (`cover.png`).
- Debug: `window.__pop` exposes the dog, cake, `micInfo()` and a `step()` for headless testing. Tested by Chuck on a phone and live.

## ocean lab
Realistic open sea in raw WebGL2, no dependencies, with a tiny penguin floating in the distance. One file (`ocean/index.html`) holds two looks behind a bottom-centre toggle (T key; choice in localStorage `ocean:look`; `?look=sunset|golden` deep-links; default golden). Each look is its own engine, run lazily the first time it is shown; the one you leave crossfades out and stops. To fold down to one look: delete the other engine's `<script>`, `<canvas>`, button and its entry in `LOOKS` (a comment at the top of the file says the same).
- `golden` (baked spectrum): a tileable wave field is baked once at load (~0.2-1s, in chunks) from two spectra (swell 96 components, chop 80), then one fragment shader samples it at four advected scales. About 1.9 ms/frame at 2.56MP on Chuck's Mac. A-style sky: sun about 7 degrees up on the right, gold glitter, teal water.
- `sunset` (swell mesh): log-spaced 224x352 mesh, 16 Gerstner waves, Jacobian foam, sun on the horizon. About 2.4 ms/frame at 1.96MP. Gentler than the first build: long swells halved, camera heave halved, horizontal displacement fades near the camera (that was what let you see under the water), chop foam toned down.
- Penguin: front-on, round, pale eyes, orange beak, splayed flippers (the OGRE-engine-style penguin from Chuck's games computing assignment, drawn from scratch in the shader, no asset shipped). Rides the swell, turns its head, twitches a flipper. About 22-25px wide on desktop. `?penguinzoom` draws it at 8x.
- Debug: `window.__ocean` is the active look's handle (`step`, `stop`, `start`, `setScale`, `config`); `window.__oceans.golden|sunset` hold both. An FPS pill (bottom-right), `?fps` or P shows a frame-rate readout (remembered in localStorage `ocean:fps`); `?bare` hides the UI for screenshots. Tunables are in each engine's `CONFIG`. Benchmark method: `__ocean.stop()`, then time N x (`__ocean.step(0.008)` + `gl.readPixels` 1px) on the page's own context.
- Perf: adaptive render scale per engine, pixel ratio capped, loop stops when hidden. Chuck tested on an iPhone 17 Pro Max: 120 fps. Older phones untried.
- Directions are archived in `ocean/archive/` (a-raymarched, b-swell-mesh, c-baked-spectrum, then b2-gentle-swell and c2-golden-spectrum, the two merged into the lab). All `noindex`. Notes page at `ocean/direction/`, screenshots (headless software render, so colours right, speed meaningless) in `direction/shots/`.
- Cover: `ocean/cover.png`, 1000x475, golden left and sunset right split by a slight diagonal (top 46%, bottom 54%), composed from `?bare` renders. `fit: 'cover'`.
- Decisions Chuck made: torn between B and C, so both ship with a toggle; B needed a gentler swell (seeing under the water broke the illusion); C should have A's vibe; penguin like the OGRE one from his uni assignment; page should be easy to fold down to one look later.

## hkg-crossing lab
The tick of a Hong Kong pedestrian crossing, synthesised with the Web Audio API (no audio files, no dependencies). The page is an isometric pixel-art Hong Kong street (`hkg-crossing/scene.js`, canvas, no image files) with the viewer-sized push button floating bottom-left of it like a FAB (the old SVG signal head is gone); the tuning controls live in a collapsed "Tune the sound" section (`?tune` opens it). Notes page at `hkg-crossing/direction/`; the first three-strike checkpoint is archived at `hkg-crossing/archive/v1-three-strike.html` (noindex).
- Flow: press the button (it also unlocks audio) -> Wait (red man, slow tick, 4s) -> Green man (solid, 10 ticks/s, 8s) -> Flashing green (bursts of five ticks at 10/s, then a 0.71s pause, 5s; was triplets, Chuck changed it to 5) -> back to red. Order and durations are `CONFIG.cycle`. The red man idle state ticks at 1/s whenever audio is on (never silent), and follows the Wait rate.
- Real-recording lightbox on the lab too: a "Hear the real one" button beside Mute opens a `<dialog>` with Chuck's reference video (youtube-nocookie, loaded on open, removed on close) and a "Play mine" button that plays the green man tick for comparison (it parks the lab's own ticks while open, restores the previous audio state on close, and stays silent in quiet hours).
- Quiet hours: `QUIET = { from: 0, to: 6 }` (local time). All ticks stop and a note shows; `?hour=N` fakes the hour for testing. A Mute button sits under the signal. Browsers block audio until a touch, so nothing ticks on a fresh load until the first press.
- Voice ("Blend", the only one Chuck kept): a sine body whose pitch falls (`drop` 0.8) plus a short triangle overtone, bandpassed noise "snap", bell-ratio partials (x2.76, x5.4, `bell` 0.4), and three strikes at once: 750 / 1300 / 1450 Hz, 120 ms, Transpose -1.00 semitone (so about 708 / 1227 / 1369 Hz). Imperfection 0.5: per-tick pitch drift and wobble, per-strike detune, length, level and timing jitter. Space: generated reverb (room 0.5s, wet 0.2: 0.3 was a bit strong on Chuck's phone) plus a short feedback "hollow" echo (0.3, 4ms) for the box-on-a-pole ring. All of these have steppers in the panel; the defaults are Chuck's ear-tuned values against a recording.
- Street scene (`scene.js`, `window.HKG_SCENE`): isometric 2:1 tiles (u along the road, v across; left-hand traffic: far lane drives +u, near lane -u), 512x384 (4:3) internal canvas with the street running off every edge (world u from -14 to 28, a near-side plaza to v=25; vehicles and pedestrians enter and leave off-canvas; the crossing sits left of and below centre, `CFG.cx`, so the tenements fill the view and the plaza stays small), drawn only with fillRect/polygon spans (pixel-exact, no anti-aliasing) from iso boxes. Static scenery (sky, skyline, road, zebra, 14 procedural tenements 10 to 22 floors tall with air-cons, scaffolding and neon signs) is pre-rendered once; vehicles (taxi, car, van, minibus, double-decker bus) and props (guardrails, lamps, trees, signal poles, bus shelter) are pre-rendered sprites; pedestrians are 12px billboards from 36 seeded looks (worker, school kid, auntie with the red-white-blue bag, tourist, delivery rider, casual; some with umbrellas) in 4 walk frames and 3 facings. Everything drawn is depth-sorted by u+v each frame (~0.1ms of JS). The lab calls `HKG_SCENE.setPhase(p)` from its own `setPhase` and `HKG_SCENE.pulse()` on each tick. Mapping: off = traffic flows, a few strollers; wait = crowd gathers at both kerbs (up to ~11 a side), car light green->amber (1s)->red (2s); walk = car red, crowd released with a 0-1.2s stagger plus a 3s scramble of new arrivals, cars yield to anyone on the road; clear = no new crossers, 4 hurrying runners; back to off = cars released after 1.2s. Vehicles and pedestrians dissolve at the slab ends instead of clipping. Time of day (local clock, `?hour=N`): four 6-hour looks, each a sky palette plus a multiply tint: morning 6-12, afternoon 12-18, evening 18-24 (night: emissive layer with lit windows, neon, lamp glows, lanterns, plus headlights/taillights and signal heads redrawn on top) and late night 0-6 (the quiet hours: moon and stars where the sky shows, thinner traffic and crowd). Season (calendar month, `?month=1-12` or `?season=`): winter Dec-Feb (pale thin trees with pink Bauhinia blossom, coats and scarves, red lanterns), spring Mar-May (blossom, drifting petals, pastel clothes), summer Jun-Aug (lush, sun umbrellas, shorts), autumn Sep-Nov (orange trees, falling leaves, amber lanterns). The look is rebuilt when the period or season changes (checked every 30s). Phones (<600px wide) get a 360px-wide crop (still 384 tall) centred on the crossing so pixels stay near 1:1; reduced motion renders static states (`warm()` simulates a few seconds per phase change, no loop). The loop pauses off-screen and when the tab is hidden. Built in a separate clone (`claude-projects/labs-clones/hkg-scene`, branch `hkg-scene`). Chuck's decisions: isometric, replace the SVG signal head, "proper HK crowd".
- Volume: fixed, no control. `CONFIG.volume` is 0.15, i.e. 30% of the original 0.5 (about 10 dB quieter; Chuck: it was louder than YouTube and games, then still too loud at 40%). The write-up demo uses the same value (`demo.js` `CONFIG.volume`).
- Autostart: the idle red-man tick starts on load (`$('power').click()` with `state.quietStart`, so no green phase flashes through the scene). Browsers keep the AudioContext suspended until the first gesture, so a first pointerdown/keydown/touch resumes it and a "Tap anywhere to start the sound." line shows until it is running.
- Sprites: iso-box sprites (`sprite()`) are drawn on a big scratch canvas and trimmed to their painted bounds, so a corner can never be clipped (the old fixed-size canvases clipped the bus shelter, benches, stalls and guardrail at their bottom-right). Signal heads use `spriteRaw()` (fixed canvas, own pixels).
- Sky and backdrop: `backC` (sky gradient, a sun that follows the period and is hidden by winter overcast, Victoria Peak, two rows of hazy far towers with antennas and crowns) is drawn first, then drifting pixel clouds (count and greyness by season, `buildClouds`/`drawClouds`), then `worldC` (the street). The far towers' windows light up at night. Only the top-right of the view shows sky; the towers poke above the near rooftops.
- Transitions: changing the period or season (clock, or the preview buttons) crossfades: `startFade()` snapshots the canvas and `render()` draws that snapshot at decreasing alpha over the new look for 0.9s (skipped under reduced motion). Late night (0-6) shuts a lot off: about 40% of buildings go fully dark, the rest keep ~16% of their windows, about half the shops and neon signs are off (deterministic hashes, `buildEmissive`), and entering it thins the traffic and crowd already on the street.
- Preview controls: a Time row (Auto, Morning, Afternoon, Evening, Late night) and a Season row (Auto, Spring, Summer, Autumn, Winter) under the scene call `HKG_SCENE.setClock(hour|null, season|null)`; null falls back to the clock or `?hour=`/`?season=`. They change the picture only: the sound's quiet hours stay on the real clock. Each row also has a Cycle button: the Time cycle moves to the next look every 5 seconds (morning, afternoon, evening, late night); the Season cycle moves to the next season each time a full day has gone round (every 20s if the Time cycle is off). The look in play is marked while cycling; picking Auto or a specific look stops that row's cycle.
- Phones (<=600px): buttons fill the row. Index hero and card buttons stack full width, the lab's preview rows are 3-column grids and Mute / Hear the real one split the row, the write-up and 404 action buttons are full width.
- Neon signs: three kinds (blade sticking out of the wall, fascia board over the shop, tall hanging banner), 12 neon colours, optional contrasting frame, pseudo-lettering built from seeded strokes (illegible on purpose), one sign in five flickers at night (drawn live each frame, the rest are in the pre-rendered emissive layer).
- Cover: `hkg-crossing/cover.webp` (from `originals/hkg-crossing/cover.png`, 1000x475, `fit: 'cover'`): the street in autumn, day on the left and night on the right, zoomed on the crossing, composed from `?bare&hour=14&month=10&phase=walk` and `?bare&hour=21&month=10&phase=wait` renders at 1280x960 (cropped 1000x475 starting at x=80,y=230, so more building and less plaza) on the same slight diagonal as the ocean cover (top 46%, bottom 54%) (`?bare` hides everything but the scene). `cover.og.jpg` is the same composite at 1200x630. Buses are 24px tall (`VT.bus.bh`); `HKG_SCENE.force(lane, type, s)` puts a vehicle on screen to check a sprite.
- Scheduling: a lookahead scheduler on the audio clock (not setTimeout drift); the lamp pulse is a timeout keyed to each tick. Focus: the master gain ramps to 0 whenever the tab is hidden or the window has fired a `blur` (`applyFocus`: visibilitychange, blur, focus; any pointerdown/keydown/touch counts as back), and returns to `CONFIG.volume`. Do NOT use `document.hasFocus()` for this: embedded browser panes report false while you are using the page, which made the sound silent (a real bug, found Nov 2026). It mutes, it does not suspend, so the clock keeps running (Chuck: "mute not pause"). Clicking into the YouTube lightbox iframe also mutes the lab, which is wanted.
- Write-up demo: `hkg-crossing/direction/demo.js` replays the sound at stages of the build behind play buttons (`HKG_DEMO.play(id)`; ids in `STAGES`, `JOURNEY` is the order for "Play all"). The page also has a lightbox (`<dialog id="real">`) that loads a real-crossing YouTube video (youtube-nocookie, only on open; Chuck's pick, credited to Traveling Erol) with a "Play mine" button to compare. Write-up order is Chuck's: goal, listen to how it grew, hollow box interlude (explains stages 11-12), imperfection after the journey, crossing, quiet hours, testing. Its synthesis is a copy of the lab's `voiceTick`, space effects and `ensureAudio`: keep the two in step if the voice changes (the stage params are in `STAGES`; the final stage is `FINAL`).
- Debug: `window.__crossing` is the state object; `window.HKG_SCENE` exposes `state`, `lanes`, `peds`, `warm(sec)`, `render()`. `?phase=wait|walk|clear` previews a moment of the crossing silently (the scene plays up to it), `?hour=N` fakes the hour (night, quiet hours). Used for the write-up screenshots.
- Tested headless only (phase order, tick gaps measured, quiet-hours note, scene timeline: crowd gathers 10 to 22, nobody crosses until walk, 37 crossing at the peak, cars released after clear). Chuck judged the sound by ear on his Mac. Not tested on iOS (audio unlock) or a phone yet.

## Defend Humanity (working title; was Shieldwall) — unlisted at `/2832a88b-b403-4314-b4c5-e3472d3450ea/`
Unlisted like the CV previews: a uuid folder, `noindex,nofollow,noarchive`, not in `LABS`, the sitemap, `llms.txt` or the README, so only people with the link find it. It is shared with friends and family until a name is chosen. When it gets a real name: `git mv` the folder, add the `LABS` entry, canonical/og tags and a cover, and drop the noindex. The code below still says shieldwall in paths and the storage key on purpose.
Wave-defence mass battle in low-poly 3D (three.js 0.160.0 from jsDelivr via an import map, like birthday-dog; vendor it if the CDN dependency matters). The script is a module. Every figure is built from boxes in code (no models, no images): one `InstancedMesh` per body part (body, head, hat, two legs, weapon, accessory) shared by everyone on the field, a blob shadow each, per-instance colour for variants/hit flash/burning; buildings are merged boxes with vertex colours (one draw call each); catapults, arrows and particles are instanced too (about 30 draw calls in battle). A flat 2D canvas (`#ov`) sits on top for health bars, floating costs and the price tag on the ghost. Fixed 60 Hz sim unchanged from the 2D version (backup of that version was kept out of the repo). Tunables at the top of the script (`CFG`, `UD` troops, `ED` enemies, `SD` defences, `BOONS`); the 3D look is the `look()` table, `VS` (figure size), `K` (sim px to world units) and `solvePose`.
- Files (no build step; plain `<script defer>` files sharing one global scope, loaded in the order listed in `2832a88b-b403-4314-b4c5-e3472d3450ea/index.html`; `import * as THREE` happens in a tiny inline module that sets `window.THREE`): `core/` is shared by every mode (`data.js` helpers, `CFG`, troop/enemy/defence definitions; `state.js` shared state and storage; `audio.js`; `scene.js` the 3D world, figures, enemy palettes, data centre, camera, overlay; `sim.js` units, grid, effects, combat, the fixed step) and `defend/` is today's game (`boons.js`, `waves.js`, `abilities.js`, `economy.js` recruit/merge/sell/place, `run.js` run flow, `bot.js`, `ui.js` HUD, shop, dialogs and screens); `main.js` is the loop and boot, loaded last. Rule: `core/` never refers to a mode's own things at load time, a mode never edits another mode's files. A future `attack/` mode (switch sides) adds its own folder and registers like `defend/` does. This is a first, mechanical split: everything still shares globals, so tighten to real module boundaries when the second mode forces the seams (the unit AI is the main one: allies follow the banner, enemies attack the gate).
- Flow: title (just "Continue game" and "New game"; New game opens the shop for wave 1: a small band of 4 spearmen and 2 archers with 210 gold, and waves 1-3 are thinned by `CFG.early` so it is back to full strength at wave 4) -> after each wave a build phase (a compact tabbed shop: Boon / Recruit / Defend / Sell, Repair under Defend; every card shows an "N owned" pill, recruit cards also list higher tiers; merge cards appear when you hold `CFG.mergeN` (10) of one kind and tier, plus the forecast of the wave's enemy counts; the whole field stays in view above it; always at the bottom, never a side panel; gold sits beside the tabs in the shop, not in the top nav, during build; tabs have icons) -> "Send wave N" floating action button (gold pill bottom-right, rides above the shop, `--shopH`) -> battle -> clear (gold bonus, survivors heal, gate +20%) -> next build. Gate at the bottom is the lose condition; fallen troops stay fallen. Score = kills x cost x 10 plus 100 x wave per clear; best and top five stored locally. Tap the field to move the banner (troops hold a formation around it). Volley (key 1, rains arrows on the thickest cluster) and Warcry (key 2) are the player's hands in battle.

- Layout and camera: the sim field is a fixed 420x900 on every screen (a narrow strip; `K` = 0.055 world units per sim px), so phone and desktop play the same field. ## Design decisions (Chuck's directions: do not regress)
Public write-up lives at `rs2-capes/direction/index.html`, linked from the index card via the `notes` field (link text "Behind the design"). Keep it in step with this list when decisions change.

**Concept and engine**
- Capes float in a dark void, each with a faint glow in its main colour. Click one to bring it to full height with mouse-driven 3D tilt. No back view. Others blur but stay faintly visible; click away or Esc returns it.
- Occasional shooting stars. A picker chooses which capes show; default three: herblore, mining, magic.
- Plain HTML/JS/CSS, no assets: capes are layered SVG shape and colour, with real 3D depth.

**Motion**
- Floating is subtle, slower still in the overview. Appearing runs small to large with natural motion (liked).
- Disappearing mirrors the appearance in reverse, shorter (it lingered before). Re-flowing the remaining capes when one is unticked was already excellent: leave it.
- Sparse background dots at varied, subtle opacities.

**Cape construction**
- Trim runs along left and right edges only, not across the bottom. The body's side edges end at the bottom rather than meeting inward.
- Layering (from OSRS): trim colour is a back layer, body on top, hood and shoulder pads in front; the trim back layer pokes out slightly at the bottom.
- Shoulder pads: redone once, then approved exactly as they are. Large focused view: "perfect", do not touch.

**Shading and light**
- Single light from screen centre shining outward, gradual section by section (the earlier version looked like folded paper). Six sections, organic slightly curved section lines, lighter vertical lines, softer light in both overview and focus. Approved.

**Per cape**
- Mining: graphic nudged slightly right to counterbalance; side trim is the cyan of the shoulder pads.
- Cooking: purple body, red side trim matching the shoulder pads (no bottom band). Emblem is a pot (not a chicken) with a neck flaring at the top, shaded round, slightly smaller, slimmed black outline that runs unbroken all the way round. Smoke wisps rectangular (not diamond), close together, with finger-joint bends: left bends left; middle is lower, tilted slightly right with its tip bent left; right matches the middle but tip tilted right.
- Magic: white body, blue trim.
- Herblore: `rs3` (default) and `osrs` variants both live in config, no UI yet; the osrs one is rebuilt from Chuck's OSRS reference. Keep both.

**Typography**
- Title bottom-left, "Chuck's Capes of Accomplishment". Jersey 10 (closest free match to the proprietary in-game font), OSRS orange `#ff981f`, 2px hard black shadow.

**Performance**
- Chuck saw forced restarts on mobile (more in the Claude app than in the browser) and asked for optimisation for mobile and weaker machines. See the perf architecture above. Resolved: all labs run smoothly on an iPhone 17 Pro Max.

**Project**
- One monorepo (`labs`) with labs.chuckwired.com as the entry point, one DO app; curate experiments out later if it gets big.
