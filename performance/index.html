Performance.

The labs are the fun part. This is the other half: how the site is put together, what each page costs to load, and what I have and haven't checked. Numbers measured on 25 October 2026.

01

The setup

It is a folder of plain HTML files in one repo, served as a static site on DigitalOcean App Platform. No framework, no bundler, no npm install. Every lab's script is inline in its own page, so there is not one JavaScript file to download separately. The single deliberate dependency is three.js on the birthday card, pinned to an exact version on a CDN. Everything else, including the two WebGL2 labs, is hand-written.

The only shared code is two small stylesheets (shared/base.css: fonts and tokens; shared/notes.css: the "Behind the design" layout) and three font files. The CSS is 2.9 KB, about 1.3 KB gzipped. Each lab keeps its own world inline, because a lab should be able to look nothing like its neighbour.

A pre-commit hook regenerates the sitemap and the crawlable lab list, then runs a check script that fails the commit on a broken link, a missing alt, a missing canonical, a stale image, or a link into the originals folder. It is about 60 lines and has no dependencies. It is the nearest thing this repo has to tests.

Rule: keep the stack small enough that I can hold all of it in my head.

Scale 0 to 800 KB. The ocean write-up has eighteen screenshots. They are all lazy-loaded, so what you download on arrival is far less.

Each page is shaped by what it is for. The index draws its cards from one list, lazy-loads covers and ships a plain-text list for anything that doesn't run script. The capes are SVG and CSS, no raster images. Pipes draws thousands of tubes in two draw calls by instancing one mesh, and lowers its pixel ratio if frames run slow. Ocean builds only the look you are viewing, pauses when the tab is hidden, and scales its resolution to keep the frame under budget. The 404 is a single self-contained file that works from any URL depth.

Rule: spend the bytes where the page's job is, and nowhere else.

03

Images and fonts

Full-quality PNGs live in an originals folder and never ship. node tools/optimise-images.mjs turns them into WebP (quality 85, covers 90), and pages only reference the WebP. That took the repo's images from 13.6 MB to 1.7 MB. A build command on the host is meant to keep the originals off the deployed site; I'll confirm that on the live URL rather than assume it.

The two typefaces used to come from Google Fonts: two extra network requests on the critical path of every page. They are now three woff2 files, 52 KB in total, with the main one preloaded and font-display: swap so text is never blocked.

Rule: keep the original, ship the small one, and make the machine do the converting.

04

Accessibility

What is in place: a language on every page, a visible focus ring on every page, text contrast of 16.1:1 for body text and 5.9:1 for the dimmer secondary text (the AA bar is 4.5:1), reduced-motion handling on every page that animates, labelled controls and nav landmarks, alt text on every image (the check script fails the commit without it), and a visible button for every keyboard shortcut (the FPS readout, the ocean look toggle).

What I haven't done: a screen-reader pass, a keyboard-only run through the WebGL labs, or a formal WCAG audit. The automated scores below catch the mechanical stuff, and the mechanical stuff is not the whole job.

Rule: an automated 100 is a floor, not a finish line.

05

Search and answer engines

For search engines: a sitemap, a robots file, a canonical link and a unique title and description on every public page, Open Graph and Twitter tags with a real preview image, and structured data (a WebSite on the index, a CreativeWork for each lab, an Article for each write-up). Unlisted pages (the birthday card, the hidden lab, the archived builds) carry noindex.

For answer engines and AI crawlers, the cheap wins are the ones that matter: the content is plain text in the HTML rather than painted by script (the index used to build its list in JavaScript, so it now ships a generated plain list as well), headings say what a section is, and the write-ups explain decisions in full sentences that a model can quote. I also publish an llms.txt. I don't have evidence that the big engines read it yet; it costs nothing, so it's in.

The honest limits: the labs themselves are WebGL canvases with almost no text, so they won't rank for anything. The write-ups carry the words. I haven't set up Search Console or any analytics, so I can't tell you how any of this performs, only that it is in place.

Rule: make the page say what it is in text, then see if anyone asks.

06

Lighthouse

Lighthouse 12 against a local copy of the site, mobile and desktop presets. A local server means no real network and no compression, so treat the scores as a floor for the markup and a rough guide for speed. The WebGL labs ran on a software renderer, so their performance numbers say nothing about a real GPU; I measured those frame costs separately (see the ocean write-up).

The honest low points, all on mobile: the ocean scores 73 and the birthday card 61 because Lighthouse throttles the CPU four times and the software renderer does the 3D work, so blocking time balloons (1.7 s and 4.6 s). That is the test rig, not a phone, but the birthday card is also the page that pulls in three.js, so it is the one I would test on a real device first. Lighthouse also flags small text on phones for the three labs with compact control labels (10 to 12 px by design); I may nudge those up.

Rule: re-run it on the deployed URL before trusting it.

07

What isn't measured yet

  • Anything on a real phone: ocean and pipes performance, touch, battery.
  • Lighthouse against the live site, with real compression and caching.
  • Real-user numbers (Core Web Vitals from actual visitors) and search performance.
  • A screen-reader pass and a keyboard-only run of every lab.
  • That the originals folder really is 404 on the deployed site.

Rule: say what you haven't checked as plainly as what you have.
